# S1 — design review: QA testability (2026-11-08)

*Step 2 of the full loop (cep sprint model §6, §8): does every rule in the design have a test that can fail when the rule is wrong? Reviewed blind: I did not read `s1/breaker/` or `coord/`. Design under review: PLAN.md §5–§6 v1.1 and the S1 plan check v2, both at cep-vscode `1d17d82` (branch `s1/integration`). Built so far: `package.json`, `scripts/check-toolchain.mjs`, `test/toolchain.test.mjs`, the placeholder grammar. Language source: cep `main` @ `1fa3a5bb`, read through git only. The owner's G0 answers are taken as settled. "Probed" means I ran it in this session; "inferred" means I read it but did not run it. Severity follows the ground rules: blocker = a rule that can be wrong with every test still green; should-fix = a weak or misleading test; later = polish.*

## Summary

- **5 blockers, 11 should-fix, 4 later.**
- **The method.** I built PLAN §5.3 as a grammar JSON from the plan's text (byte-equal to the plan-check QA's build). I wrote the six §6.1 unit files and the plan check's §6 counter-examples as real `vscode-tmgrammar-test` files, all generated by script so the caret columns are exact. I then ran 271 mutant grammars against four layers: the §6.1 files, the counter-examples, the 19 fixture snapshots, and a reference `check-keywords` written from PLAN §5.5.2.
- **The headline.** The §6.1 files catch 181 of 271 mutants. Adding the counter-examples brings that to 198. In the remaining gap, 31 mutants pass every layer (10 grammar rules and 21 keyword placements), and 37 more are caught only by a snapshot.
- **Why snapshot-only is not enough.** A snapshot is generated from the grammar under test. It cannot show that grammar wrong, only that it later changed; at build time only the hand review sees those 37. So I count snapshot-only coverage as "no failing test".
- **The fix is cheap.** One extra unit file of about 90 assertion lines (D-Q1 to D-Q4) brings the unit layer to 265 of 271. The other 6 are four order swaps that cannot change any token, one rule that only the checker covers, and one rule that only matters on input cep rejects.
- **The blockers:**
  - D-Q1: 49 of the 98 non-reserved keywords can sit in the wrong category with every unit test green.
  - D-Q2: the `\n`, `\t` and `\r` escapes, raw `"""` strings and most of the E-STR-002 class have no test.
  - D-Q3: several name rules have no test: backticked names with a space, a backticked `insert into` target, and the declaration keyword's `\b`.
  - D-Q4: three punctuation captures and the namespaced-call lookahead have no unit test.
  - D-Q5: `sync-upstream`'s core rule, "read the ref through git, never the working tree", has no test.
- **The tooling and red-first plans are mostly runnable.** The built `check-toolchain` layer is sound: 5/5 tests pass on the real script, and 5/5 fail with the script absent or as an exit-0 stub. The weak spots:
  - the named unit mutant (D-Q6);
  - the checker's stub run and tests 7 and 11 (D-Q7);
  - vacuous "nothing changed" tests (D-Q14);
  - the tooling tests' dependence on the machine's git config (D-Q12).

## Findings

### D-Q1 — blocker — PLAN §5.3 keyword table (lines 291–303); §6.1 `keywords.test.cep` (lines 599–616)

**Finding.** The checker proves each word is in exactly one category. Nothing proves it is in the right one. 49 of the 98 non-reserved words have no unit assertion, so any of them can be moved to a wrong category with every unit test and the checker green. 21 of them are in no fixture either, so not even a snapshot sees them.

**Evidence.**
- 98 mutants, each moving one word to another category: unit 0 and checker 0 for 49 of them; all layers 0 for 21 (`design-qa/out/mutants-ws2.txt`, rows `K …`).
- All-layer survivors: `param stream table allow insert arrival ascending todo asc has_cs contains_ci starts_with_ci ends_with_ci has_any_cs has_all_ci has_all_cs contains_any_cs contains_all_ci contains_all_cs matches_ci contains_match_cs`.
- Snapshot-only: `intent by of ttl once for skip past last late events drop first window on close change due end bounded idle expect given then desc starts_with_cs ends_with_cs contains_any_ci`.

**Change.** In `keywords.test.cep`, assert every word of every category with its category scope. Generate the lines by script from the §5.3 table.
- Write the declaration words as `language; param; stream; table; rule;`, so no word is followed by a name that `declarations` would capture.
- Break the clause line after `insert`, so `insert into window` does not match `insert-target`.
- Write `raw` as `x raw y`.

`design-qa/mini/test/add/add.test.cep` has the lines. It is green on the plan grammar, red on the placeholder, and kills all 98 movement mutants. (An alternative is a checker rule (h) that compares each category's words with the table held as a constant.)

### D-Q2 — blocker — PLAN §5.3 `string-escapes` and `strings`; §6.1 `strings.test.cep`

**Finding.** SPEC §2.4 lists the valid escapes exhaustively. Three of them, `\n`, `\t` and `\r`, are never asserted in a normal string. Raw `"""` strings are never tested with a backslash. The E-STR-002 class is tested with `\x` and `\U` only.

**Evidence.**
- Dropping `n`, `t` or `r` from the valid class: unit 0, checker 0; only lexical.cep's snapshot sees it.
- Adding escapes to the `"""` rule: 0 in every layer.
- Adding `0` to the valid class, or narrowing the invalid rule to letters: 0 in every layer.

**Change.** Add:
- `x '\n\t\r' "\n\t\r"` → each of the 6 escapes → `constant.character.escape.cep`;
- `x '\0 \$ \a'` → `\0`, `\$`, `\a` → `invalid.illegal.escape.cep`;
- `x """raw \n stays"""` → `\n` → `string.quoted.triple.double.cep - constant.character.escape.cep`.

### D-Q3 — blocker — PLAN §5.3 `backticked`, `declarations`, `insert-target`; §6.1 `names.test.cep`

**Finding.** Five name rules can be wrong with every test green, each on valid cep:
- a backticked name may hold spaces;
- an `insert into` target may be backticked;
- the declaration keyword needs its `\b`;
- the `table` and `rule` keyword captures inside `declarations`;
- `\s+` between keyword and name.

**Evidence.** Mutants with unit 0 and checker 0:
- `T backticked no space`: 0 in every layer;
- `T insert-target NAME without backticked`: 0 in every layer;
- `T declarations no \b`: 0 in every layer;
- `R declarations.table cap1` and `R declarations.rule cap1`: snapshot only;
- `T declarations need one space`: snapshot only.

**Change.** Add:
- `` x `agent events` `` → `variable.other.quoted.cep`;
- `` insert into `agent-events`; `` → `` `agent-events` `` → `entity.name.type.stream.cep`;
- `table Blocked (a string)` → `table` → `storage.type.declaration.cep`;
- `rule LexicalTorture` → `rule` → `storage.type.declaration.cep`;
- `stream  Foo (a string)` (two spaces) → `Foo` → `entity.name.type.stream.cep`;
- `select upstream as u` → `as` → `keyword.control.clause.cep`. Without the `\b`, `stream as` matches and `as` becomes a stream name.

### D-Q4 — blocker — PLAN §5.3 `comments`, `strings`, `function-call`; §6.1

**Finding.** Three emitted scopes are never required by a §6.1 assertion:
- `punctuation.definition.string.begin.cep` and `…end.cep`;
- `punctuation.separator.namespace.cep`, which nothing in the unit or counter-example sets requires;
- the block comment's `/*` `*/` capture of `punctuation.definition.comment.cep`, which only the line comment's `--` asserts.

The namespaced call's `(?=\()` has no test at all.

**Evidence.**
- Renaming the namespace separator: unit 0, snapshot 2.
- Dropping the block-comment captures: unit 0, snapshot 2.
- Renaming string begin/end: §6.1 0, counter-examples 14/15.
- `T fn.namespaced no lookahead`: 0 in every layer.
- The converse scope lint lists the three scopes (§3).

**Change.** Add:
- `x /* inline */ y` → `/*` and `*/` → `punctuation.definition.comment.cep`;
- `x 'read'` → col 2 `…begin.cep`, col 7 `…end.cep`;
- in literals, `math:round` → `:` → `punctuation.separator.namespace.cep`;
- `x {agentId:lead}` → `agentId - entity.name.namespace.cep` and `:` → `punctuation.separator.key-value.cep`.

Make the converse lint a test (D-Q10).

### D-Q5 — blocker — PLAN §5.5.1 (lines 375, 381); §6.4 `sync-upstream` (lines 683–688)

**Finding.** The script's defining rule is "read the ref through git's object store, never the cep working tree". A sync that reads `<cep>/<path>` from disk passes all five planned cases, because in each the throwaway repo's working tree equals its ref. Card line 4 also passes on such a sync whenever cep's checked-out tree equals the target in those paths. QA's plan-check review found exactly that case: Q4 saw no diff in these paths.

The raw-bytes rule (no line-ending change) is also untested, because the throwaway files are only "a few small files".

**Evidence.** By construction: none of the five cases has a ref that differs from the working tree (inferred). `git ls-files` and `git cat-file` behave as the spec says (probed in `design-qa/gitprobe`).

**Change.** Add a case:
1. In the throwaway repo, commit on `main`: `keywords.go`, one example with CRLF line endings and no final newline, and the 7 invalid names.
2. Create and check out a branch `other` that changes those bytes, and leave one more uncommitted edit.
3. Run `sync-upstream <repo> --ref main --out <tmp>`.
